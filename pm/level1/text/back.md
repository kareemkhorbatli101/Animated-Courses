# Grammar reference

Every structure in this book, in unit order. The second column is the mistake it prevents, which is
the column worth reading twice.

## Starting Point · Four questions

| | |
|---|---|
| **A project has a start, an end and a result** | ordinary work has none of the three, and needs none |
| **The four questions** | what are we making · when will it be finished · what will it cost · who decides |
| **Two ways to answer question two** | a date · or a date and the condition it depends on |
| **A number with no unit is not an answer** | *soon*, *about*, *roughly* are all the same answer: no |

## Unit 1 · *be* and *have*; one and many

| | |
|---|---|
| **a project **has** an end** | *be* for what something is, *have* for what it contains |
| **one project, many projects** | and *a programme* is not a bigger project, it is a different noun |
| **a programme **is** a group of related projects** | *related* is the word doing the work in that sentence |
| **the register said twenty-nine projects** | eleven of them had no end date, so eleven of them were something else |

## Unit 2 · Prepositions of time

| | |
|---|---|
| ***on* the 4th, *in* March, *at* nine** | the three that appear in every schedule |
| ***by* Friday** and ***until* Friday** | one is a deadline, the other is a period, and they are not the same promise |
| ***for* three weeks, *since* March** | a length, and a starting point |
| **a bar with no condition is a wish** | the preposition is correct and the date is still not a commitment |

## Unit 3 · Part and whole

| | |
|---|---|
| **the structure **is divided into** levels** | the passive for how something is organized |
| **a package **belongs to** one branch** | if it belongs to two, two people will think it is theirs |
| **every part **is included in** the whole** | and nothing that is not in the whole is in a part |
| **a four-month package reports *fine* for eleven weeks** | because a package too big to finish is also too big to be wrong |

## Unit 4 · *responsible for*, *accountable for*, *report to*

| | |
|---|---|
| **responsible for** the work | you do it |
| **accountable for** the result | you answer for it, and you cannot share it with a department |
| **report to** a person | and a department is not a person |
| **a limit: 20,000 and two weeks** | authority without a number in it is authority nobody can use |

## Unit 5 · Comparatives

| | |
|---|---|
| **faster, cheaper, more expensive** | short words take *-er*, long words take *more* |
| **less scope, fewer features** | uncountable and countable |
| **as cheap as, not as fast as** | for comparing without a winner |
| **the triangle has no corner for unpaid Saturdays** | which is where the fourth corner actually went |

## Unit 6 · Modals of priority

| | |
|---|---|
| **it **must** be in the first release** | and a *must* is a thing the release cannot ship without |
| ***should*, *could*, *will not*** | four levels, and the fourth is the only one that saves time |
| **41 *musts* is not a priority list** | it is a list |
| **every *will not* needs a date and a name** | otherwise it is a *not yet* that nobody will ever reopen |

## Unit 7 · *will* and *by*

| | |
|---|---|
| **it **will be** finished **by** the 8th** | *will* for the commitment, *by* for the deadline |
| **three dates, not one** | finished by the 8th · circulated by the 10th · decided on the 17th |
| **a gate has three answers** | go · stop · go with conditions — and the third one needs a date |
| **forty pages two days before a gate** | eleven pages read: the date was met and the decision was not made |

## Unit 8 · *may*, *might*, *probably*

| | |
|---|---|
| **it **might** be late** | for something that has not happened yet |
| ***probably*, *possibly*, *unlikely*** | words for how likely, used before anybody has a number |
| **a risk is not an issue** | one has not happened; the other is today's problem |
| **61 rows, 22 of them one word** | a register that cannot be read is a register that is not read |

## Unit 9 · Sequencing

| | |
|---|---|
| ***first*, *then*, *after that*, *next*, *finally*** | the order of a process |
| ***once* the rules are written** | for the thing that must happen before the next thing can |
| **four stages, and the third is the quiet one** | the stage everybody wants to skip is the one that makes the rules |
| **one new joiner puts a team back two days** | which is a cost of hiring that nobody puts in a plan |

## Unit 10 · Requests and permission

| | |
|---|---|
| ***Can I*, *Could I*, *May I*** | asking, from informal to formal |
| ***You can* / *You cannot*** | giving and refusing |
| ***You have to* / *You do not have to*** | necessary, and not necessary — and these two are easy to mix up |
| **four lines, not two pages** | an expensive record is a record people stop making |

## Unit 11 · The passive for reporting

| | |
|---|---|
| **it **was reported** as amber** | the report matters, not who wrote it |
| **the money **has been spent*** | present perfect passive, for what is now true |
| **decisions **are recorded** in the minutes** | the present passive for a process |
| ***a mistake was made*** | the passive that hides a person: use it for the process, never for the blame |

## Unit 12 · Review

| | |
|---|---|
| **six boxes** | result · date · cost · decider · risks · measure |
| **one number or one name in every box** | writing is not the same as content |
| **the stranger test** | could somebody who was not in the room act on this box tomorrow? |
| **a definition belongs to the document it is in** | four documents define *project*, and none of them travels |

# The British layer

This book is written in American English, and the series carries a switchable British layer: a fixed
list of words is respelled at build time. The list lives with the series rather than in this book.

What the layer does not touch:

1. **The date.** Write the month in letters where the sentence is prose, and the international format
   where it is data.
2. **A quoted document keeps its own spelling.** Every standard, paper and published method quoted in
   this book is quoted as published, even where its spelling differs from the text around it.
   Correcting a published document inside a quotation is an alteration.
3. **A document number keeps its published form.** ISO 21506:2018, ISO 31000:2018 and ISO 9000:2015
   are citations, not words.
4. **Money has no symbol anywhere in this series.** The unit is whatever currency your project uses.
   A number without a symbol is readable in every country; a number with the wrong symbol is readable
   in none.
5. **A name is never respelled.** Adamiecki, Gantt, Barnes, Clegg and Tuckman are spelled as they
   are published.

One word to note. **Programme** keeps that spelling everywhere in this series, in the American
edition as well as the British one. It is not an oversight. *Programme* is the term **ISO
21506:2018** defines — a group of related projects, managed together for a benefit — and *program*
is a different word in that vocabulary. Americanizing it would rename a defined term, which is a
worse error than an inconsistent page.

# Sources

Twelve source bodies carry the twelve reading texts, one per unit, and the Starting Point carries
none. Every one is a published standard, paper or named method, cited with its edition or its date,
and every reading text prints what the publisher or the author says the document does **not** cover.
No source appears in any other book of this series or in its four sister series, and no figure is
used twice. The series note is in `SOURCES.md`.

| Unit | Source | What the text prints |
|---|---|---|
| **1** | ISO 21506:2018, *Project, programme and portfolio management — Vocabulary* | It defines terms and gives no method, no process and no requirements |
| **2** | Karol Adamiecki's harmonogram, 1896; Henry Gantt's charts, c. 1910–1919 | Neither inventor gave the chart the meaning we now hang on it; a bar is a drawing of an intention |
| **3** | ISO 21511:2018, *Work breakdown structures for project and programme management* | It is guidance; it fixes no number of levels and no package size |
| **4** | ISO 21502:2020, *Project, programme and portfolio management — Guidance on project management* | Guidance, not requirements; it names roles and does not say who at your company holds them |
| **5** | Martin Barnes's time–cost–quality triangle, 1969 | Its author later said the triangle was never meant to be the whole of the job |
| **6** | MoSCoW prioritization, Dai Clegg, 1994; later carried by the DSDM framework | It orders requirements and does not tell you how many *musts* a release can hold |
| **7** | ISO 21500:2021, *Project, programme and portfolio management — Context and concepts* | The same number named a different document in 2012; the edition is part of the citation |
| **8** | ISO 31000:2018, *Risk management — Guidelines* | Guidelines, not for certification; it contains no matrix, no scoring scheme and no thresholds |
| **9** | Bruce W. Tuckman, *Developmental sequence in small groups*, *Psychological Bulletin*, 1965 | A review of about fifty studies, most of them therapy and laboratory groups, not project teams; the fifth stage was added in 1977 |
| **10** | ISO 10007:2017, *Quality management — Guidelines for configuration management* | Guidelines, not requirements; no form, no approval limits, no definition of a significant change |
| **11** | ISO 21505:2017, *Project, programme and portfolio management — Guidance on governance* | Guidance, not requirements; no colors, no thresholds, no meeting frequency, no board membership |
| **12** | ISO 9000:2015, *Quality management systems — Fundamentals and vocabulary* | A vocabulary and concepts document; no requirements, no templates, no method, and not itself a certification standard |

Twelve admissions, one per unit, worth reading as a list of their own.

- **Unit 1.** A vocabulary tells you what a word means in that document. It does not tell you what to
  do, and it does not stop your company calling a department a project.
- **Unit 2.** The chart is 130 years old and it still cannot show a condition. Every bar is drawn with
  the same confident edge, whether the date is contracted or hoped for.
- **Unit 3.** The guidance will not tell you how small a package should be. The only working answer is
  *small enough that somebody could be wrong about it in less than a month*.
- **Unit 4.** Roles are named in the standard and filled in your building. A department cannot be
  accountable, because a department cannot be asked a question.
- **Unit 5.** Three corners, and the thing that actually moved was in none of them: eleven unpaid
  Saturdays.
- **Unit 6.** A method for ordering requirements cannot stop you writing forty-one *musts*. Only a
  person can do that, out loud, in a room.
- **Unit 7.** One document number, two different documents, nine years apart. *The standard* names
  nothing; *the 2021 edition* names a document.
- **Unit 8.** The most widely used risk tool in the world — the five-by-five matrix — is not in ISO
  31000 at all. Somebody put it in a training course and it traveled.
- **Unit 9.** Four stages that everybody can name, from a 1965 review of groups that were mostly not
  project teams, and the author never claimed otherwise.
- **Unit 10.** The rule was always right. The record was made so expensive that people chose between
  helping the project and following the process.
- **Unit 11.** Nobody lied. Four true amber reports in a row told the board nothing, because a status
  cannot report that nothing has moved.
- **Unit 12.** A definition is right inside its own covers and nowhere else. The only definition that
  governs your project is the one you and your sponsor wrote down.

# A note on everything else in this book

Every person, team, company, project, number and incident in this book is invented. Lindhurst does
not exist; neither does the Calder job, the pump station, the racking supplier or any of the
fourteen people who appear in the dialogues. The documents are real and cited; the stories around
them are written to teach the language, and any resemblance to a real organization is accidental.

Nothing in this book is legal, financial or contractual advice. Where a sentence sounds like a rule —
*two months of amber is red*, *20,000 and two weeks*, *five risk rows* — that is one invented
company's internal practice, printed because a concrete number teaches better than an abstraction.
Your own numbers belong to you and your sponsor.

# Closing

You began this book able to say that a project was late. You end it able to say **which** date, from
**which** baseline, approved by **which** named person, against **which** published document — and
what that document admits it does not cover.

Twelve documents, and one habit: find the published rule, print what it does not cover, and write a
number in the box instead of a sentence about the box.

Six sentences to take with you, one from each half of the book.

From Unit 1: **does it have a start, an end and a result?**

From Unit 3: **is this package small enough to be wrong about in under a month?**

From Unit 5: **which corner actually moved, and who paid for it?**

From Unit 7: **which edition are we talking about?**

From Unit 10: **is this change a decision, or a surprise for somebody else?**

From Unit 12: **how will anybody know whether it worked?**

That last one is box 6. It was empty in eleven of the eighteen briefs that started this series, and
filling it in is the only thing in this book that will ever tell you whether any of the rest of it
helped.
