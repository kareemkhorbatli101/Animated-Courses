# Grammar reference

Every structure in this book, in unit order. The second column is the mistake it prevents, which is
the column worth reading twice.

## Starting Point · What a format is for

| | |
|---|---|
| **A format is an agreement between two systems** | and it holds only while both read the same document |
| **Three things a field needs** | what it means · how it is written · which published document says so |
| **The four questions** | which document, and which edition · a zone or an offset · how many bytes, and in which encoding · a MUST or a SHOULD |
| **An edition is part of a citation** | *the standard* names nothing; *the 2019 edition* names a document |

## Unit 1 · Present simple; *on*, *in*, *at*

| | |
|---|---|
| **the week **starts** on Monday** | a rule, not an event: present simple for what is always true |
| ***on* a date, *in* a month, *at* a time** | the three prepositions that appear in every schedule |
| **week 01 contains 4 January** | the test for the first week; the week-based year can differ from the calendar year |
| **2019, replacing 2004** | the edition that is current, and the one your library still holds |

## Unit 2 · Telling the time; *there is / there are*

| | |
|---|---|
| **an instant is stored in UTC** | one line that removes a class of bug |
| **a plan is a local time and a zone name** | not an offset: the offset is a result, not an input |
| ***there are* two offsets in that zone this year** | *there is / there are* for what a zone contains |
| **the database is updated several times a year** | so the answer to *what time is that* has a version |

## Unit 3 · Countable and uncountable; *how many / how much*

| | |
|---|---|
| ***how many* bytes, *how much* text** | the field length question, asked correctly |
| **a code point is not a character is not a byte** | three countable things, and users count none of them |
| **one grapheme cluster, several code points** | what the reader calls one letter |
| **data *is* uncountable in practice** | and *datum* will make you sound like 1974 |

## Unit 4 · Comparatives

| | |
|---|---|
| **binary64 is *more precise than* binary32** | 15 to 17 digits against 6 to 9 |
| **`0.1 + 0.2` is not equal to `0.3`** | the single most repeated surprise in this book |
| **NaN is not equal to itself** | so an equality test is the wrong tool |
| **compare *to within* a tolerance** | for measurements; money is not compared this way at all |

## Unit 5 · Plurals and quantities

| | |
|---|---|
| ***most* currencies, *some*, *a few*** | two minor digits, none, three |
| **0 decimal place**s** | zero takes a plural in English |
| **the amount travels with the code** | a number with no code is not money |
| **two lists: current and historical** | a withdrawn code still has to print |

## Unit 6 · *have to* and *must*

| | |
|---|---|
| **the field *must* be text** | a leading zero is part of the number |
| ***must not* ≠ *do not have to*** | forbidden against not necessary; the two most swapped modals in specifications |
| **at most fifteen digits** | a limit you can quote for a career; *exactly twelve* is a list of your test data |
| **accept widely, store narrowly** | any form from a person; one form in the database |

## Unit 7 · The present passive

| | |
|---|---|
| **codes *are assigned* by the maintenance agency** | the list is not yours to invent |
| ***is withdrawn*, *is reserved*** | and reserved is not withdrawn: GB is the code, UK is reserved |
| **the name *is displayed*, the code *is stored*** | a name is not an identifier |
| **use the passive for standards and the active for yourself** | *I used the wrong code* is three words shorter than the alternative |

## Unit 8 · The zero conditional

| | |
|---|---|
| **if the first digit *is* 4, the client *made* the mistake** | both halves present simple; never *will* in the *if* half |
| ***if* leaves it open, *when* says it will happen** | and a new code **will** appear |
| **five classes, not fifty codes** | an unknown code is handled as the first of its class |
| **log the code, handle the class** | a failure that will not name its own cause costs an hour |

## Unit 9 · *will* and sequence

| | |
|---|---|
| **your code *will* keep working** | the promise the second number makes |
| **a timetable takes the present simple** | *the release goes out monthly*; one release takes *will* |
| ***first*, *then*, *after that*, *finally*** | decide whether anything breaks, **then** choose the number |
| **0.y.z promises nothing** | and 0.9.4 does not mean *nearly 1.0* |

## Unit 10 · Modals of obligation

| | |
|---|---|
| **MUST, SHOULD, MAY** | no choice · a choice with understood consequences · genuinely optional |
| **capitals carry the meaning** | lowercase *must* is ordinary English |
| **sparingly** | only for interoperation or harm; thirty-one MUSTs is an unreadable document |
| **what breaks without it** | one sentence beside every MUST, or it is not a MUST |

## Unit 11 · Possessives

| | |
|---|---|
| **the *reader's* language, the *readers'* languages** | one, and more than one |
| ***its* parts, and *it's* = *it is*** | the most common mistake in technical English |
| **more specific is not more correct** | *en-GB* falls back to *en*, and the reader is well served |
| **their order, not ours** | the preference list arrives with every request |

## Unit 12 · Review

| | |
|---|---|
| **four readers, four questions** | a document for everybody is a document for nobody |
| **a decision with its reason beside it** | the only part that survives the team |
| **reason unknown** | an honest gap beats a reconstructed reason |
| **name the reader who cannot ask** | the person who joins in two years |

# The British layer

This book is written in American English, and the series carries a switchable British layer: a fixed
list of words is respelled at build time. The list lives with the series rather than in this book.

What the layer does not touch:

1. **The date.** Write the month in letters where the sentence is prose, and the international format
   where it is data.
2. **A quoted standard keeps its own spelling.** Every standard, recommendation and specification
   quoted in this book is quoted as published, even where its spelling differs from the surrounding
   text. Correcting a published document inside a quotation is an alteration.
3. **A code, a tag and an identifier are never respelled or reformatted.** `GB`, `KWD`, `en-GB`,
   `zh-Hant`, `binary64`, `UTF-8` and `3.0.0` are the same in both variants.
4. **A requirement keyword stays in capitals.** MUST, MUST NOT, SHOULD, SHOULD NOT and MAY carry
   their meaning only in capitals, and the layer leaves them alone.
5. **A document number keeps its published form.** ISO 8601-1:2019, RFC 9110, BCP 47 and
   ISO/IEC/IEEE 42010:2022 are citations, not words.

# Sources

Twelve source bodies carry the twelve reading texts, one per unit, and the Starting Point carries
none. Every one is a published standard, recommendation or specification, named with its edition or
its date, and every reading text prints what the publisher says the document does **not** cover. No
source appears in any other book of this series or in its three sister series, and no figure is used
twice. The series note is in `SOURCES.md`.

| Unit | Source | What the text prints |
|---|---|---|
| 1 | **ISO 8601-1:2019** and **ISO 8601-2:2019**, *Date and time — Representations for information interchange*, with **RFC 3339** | The **2019** two-part edition **replaced the 2004 edition**. Calendar, **ordinal** and **week** dates; the rule that **week 01 is the week containing 4 January**; the week **starts on Monday**; so **1 January 2027 falls in week 2026-W53** and the week-based year is not the calendar year. **RFC 3339 is a profile**, not the standard: it narrows the choices for one purpose |
| 2 | **The IANA Time Zone Database**, released as dated versions such as **2024a** and **2025b**; the **2022 resolution of the General Conference on Weights and Measures** | An **offset** is a number of hours and minutes; a **zone name** is a set of rules **that changes**. The database is **updated several times a year**, so a future local time has **a version as well as a value**. The **last leap second was added on 31 December 2016**, and the 2022 resolution provides for **ending the practice by 2035**. **Store an instant in UTC; store a plan as a local time and a zone name** |
| 3 | **The Unicode Standard**, version **15.1** (**September 2023**) and version **16.0** (**September 2024**) | **149,813** characters in 15.1 and **154,998** in 16.0 — the number **grows with each version**. The code space runs **U+0000 to U+10FFFF**, which is **1,114,112** positions. **UTF-8 uses one to four bytes** per code point. **A byte is not a code point and a code point is not what a reader calls a character**: a grapheme cluster may be several code points. **Normalization** gives two spellings of one word the same form; **it is not optional if you compare names** |
| 4 | **IEEE 754-2019**, *IEEE Standard for Floating-Point Arithmetic* | The **2019** edition follows **2008**, which followed **1985**. **binary32** carries **24 bits** of significand, about **6 to 9 decimal digits**; **binary64** carries **53 bits**, about **15 to 17**. **`0.1 + 0.2` is not equal to `0.3`** in either. The standard defines **two zeros**, **two infinities** and **NaN**, which **is not equal to itself**. **Money is a whole number of minor units**; a measurement is binary64 compared **to within a tolerance**. Decimal formats are in the standard too, and are not what most languages give you by default |
| 5 | **ISO 4217**, *Codes for the representation of currencies*, **2015** edition, with the code list **maintained and published by its maintenance agency** | An **alpha** code of three letters, a **numeric** code of three digits, and the **number of minor digits** — **2** for most currencies, **0** for some, **3** for a few. So the same stored number `1250` is **three different amounts** in EUR, JPY and KWD, one of them a thousand times another. Codes are **added and withdrawn**, so a system needs a **current** list and a **historical** list. The standard gives **no exchange rates** and does not govern **national cash-rounding practice** |
| 6 | **ITU-T Recommendation E.164**, *The international public telecommunication numbering plan*, **November 2010** version | **At most fifteen digits** in an international number, country code included. A country code of **one to three digits**, then the destination and subscriber parts. **The plus sign is not a digit**: it stands for the international prefix, **which differs by country**. A number **can begin with a zero**, so the field is **text**. Written presentation belongs to **E.123**; **extensions**, whether a number is mobile, and **national short codes** are **outside** E.164 |
| 7 | **ISO 3166-1**, *Codes for the representation of names of countries and their subdivisions — Part 1: Country codes*, **2020** edition, with the list **maintained by the ISO 3166 Maintenance Agency** | **alpha-2**, **alpha-3** and **numeric** forms. Codes are **assigned**, **withdrawn** and then **reserved** so that they are not reused immediately; **UK** and **EU** are **exceptionally reserved**, and the code for the United Kingdom is **GB**. Subdivisions are **Part 2**, formerly used codes are **Part 3**. The standard assigns **no language, currency, tax rule or address format**, and **country names are drawn from sources outside it** |
| 8 | **RFC 9110**, *HTTP Semantics*, **June 2022** | It **replaced the 2014 specifications**, which replaced one from **1999**; **the five classes have not changed**. First digit **1** informational, **2** successful, **3** redirection, **4** **client** error, **5** **server** error. A client **must understand the class** and **may treat an unrecognized code as the first code of that class**, which is why **new codes can be added safely**. The code list is a **registry maintained by IANA**: the set of codes is **open**, the set of classes **closed**. **401 means unauthenticated**; 403 means refused. The document defines **no error body format and no retry policy** |
| 9 | **Semantic Versioning 2.0.0** | **MAJOR.MINOR.PATCH**: the first number for an **incompatible** change, the second for a **compatible addition**, the third for a **compatible fix**, with lower parts **reset to zero**. **0.y.z means the public interface is not to be considered stable and anything may change** — so 0.9.4 promises **nothing**. A **pre-release** has **lower precedence** than the plain version, and build information is **ignored** in precedence. The public interface **must be declared**, or the numbers mean nothing. The specification **enforces nothing**: the promise is kept by people |
| 10 | **RFC 2119**, *Key words for use in RFCs to Indicate Requirement Levels*, **March 1997**, with **RFC 8174**, **May 2017** — together **BCP 14** | **MUST / REQUIRED / SHALL**, **MUST NOT / SHALL NOT**, **SHOULD / RECOMMENDED**, **SHOULD NOT**, **MAY / OPTIONAL**. **SHOULD** permits departure **where the full implications are understood and carefully weighed**. An **optional** item carries an **interoperation** obligation on both sides. The keywords are to be used **with care and sparingly**, **only where required for interoperation or to limit harmful behavior**. After 2017, **only the capitalized forms carry the meaning**. The documents **confer no standards status and test nothing** |
| 11 | **BCP 47** — **RFC 5646**, *Tags for Identifying Languages*, **September 2009**, and **RFC 4647**, on **matching** — with the **IANA Language Subtag Registry** | Subtags in order: **language**, **script** (four letters), **region** (two letters or three digits), then variants. The conventional capitalization is a **convention**: tags are **compared without regard to case**. A longer tag is **more specific, not more correct**, and **matching removes subtags**: *en-GB* falls back to *en*. A reader's browser sends **an ordered list of preferences**, and **their order decides**. A tag gives **no currency, no date format, no translation** and **does not say where the reader is** |
| 12 | **ISO/IEC/IEEE 42010:2022**, *Software, systems and enterprise — Architecture description*, **second edition** | It **replaced the 2011 edition**, which grew out of a document from **2000**. **Stakeholder**, **concern**, **architecture viewpoint**, **architecture view**. A description **identifies the stakeholders and their concerns**, and **each concern is framed by at least one viewpoint** — a rule that finds both common faults: a section with no reader, and a reader with no section. It provides for **decisions recorded with their rationale** and for **correspondences** between views. It prescribes **no viewpoint set, no notation, no tool, no template and no process**, and **says nothing about whether an architecture is good** |

**Twelve honesty notes, printed in the units as well as here.**

- **Unit 1.** The format that exists to remove ambiguity has three ways to write one day, and the
  week-based year disagrees with the calendar year for a few days most years. A date written without
  saying which representation it uses can still be read two ways.
- **Unit 2.** The rules that convert a local time to an instant are a file that changes several
  times a year, and a government can change them with weeks of notice. A meeting booked for next
  November has an answer that is not yet known.
- **Unit 3.** The number of characters is not a fixed quantity: it grows with every version of the
  standard. A field length of twenty means nothing until somebody says twenty **of what**, and the
  three candidate answers differ by a factor of four.
- **Unit 4.** Arithmetic that a standard describes exactly still gives an answer that looks wrong to
  everyone who has not read it, and the standard cannot help with that. Money is not a hard problem
  because of the arithmetic; it is hard because the default type is the wrong one.
- **Unit 5.** The number of decimal places is a property of the currency, and the assumption that it
  is two is almost never written down as a decision. It arrives with the first currency a company
  supports and ends up in a template, a spreadsheet and a test fixture, with no author.
- **Unit 6.** The one rule the recommendation gives about length is an **upper limit**. Nearly every
  validation failure in this area comes from a team replacing it with an exact length taken from the
  numbers they could see, in one country, on one afternoon.
- **Unit 7.** The most political file in a product is usually written in twenty minutes from memory.
  The standard protects you only if you take the list from the published source, keep the date of
  your copy, and can say both of those in one sentence to a customer who is upset.
- **Unit 8.** The protocol was designed so that a client written years ago keeps working when new
  codes appear — and a client written against a list of eleven codes throws that away. The design is
  sound and the failure is ours, every time.
- **Unit 9.** Nothing enforces a version number. The specification is a promise kept by people, and
  the one pressure that reliably breaks it is a meeting in which a major version is said to look
  alarming.
- **Unit 10.** The strong word works because it is rare, and nothing stops an author from using it
  everywhere. A conformance section with thirty-one requirements has no requirements, because the
  reader cannot find the three that matter.
- **Unit 11.** Choosing a reader's language from their location fails for a minority everywhere and
  a majority nowhere, so it never appears in anybody's numbers. The better answer arrives with every
  request, unused.
- **Unit 12.** The standard is about the description and not the architecture. A clear description of
  a poor design is a clear description — and that is still worth having, because it lets somebody
  see what is wrong.

# Closing

You began this book able to say that a date was wrong. You end it able to say **which** date, in
**which** representation, from **which** edition of **which** document — and what that document
admits it does not cover.

Twelve standards, and one habit: find out what the published rule actually says, write down what it
does not cover, and name the person who will be hurt if you get it wrong.

Four sentences to take with you.

From Unit 1: **which document, and which edition?**

From Unit 2: **is that a time zone or an offset?**

From Unit 3: **how many bytes, and in which encoding?**

From Unit 10: **is that a MUST or a SHOULD?**

And from Unit 12, which is where this book ends: **a decision without a reason beside it will be made
again, next year, by somebody who has not met you — so write the reason down, in one sentence, every
time.**
