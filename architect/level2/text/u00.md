# Starting Point · What an Interface Promises
%%SUB Six structures you already have, and the promise they are for%%
%%GOALS
Review the grammar of Book 1
Say what an interface promises
Ask the four questions of this book
%%

An interface is a promise made in writing to somebody you will never meet. This book is about how
that promise is written, what it covers, and — the part nearly everybody misses — what it does not.

### 1 · Six structures you already have

%%FIG b00-f1 | A single review sheet with six boxes. Each box has a heading — the present simple, the present passive, countable and uncountable, comparatives, modals of obligation, and the zero conditional — and one short example sentence from an integration engineer's working day.%%

**1A  Read the six examples aloud with a partner. Which two do you use most?**

| | |
|---|---|
| **The present simple** | The service **returns** a code in the two hundreds. |
| **The present passive** | The field **is validated** before the record **is stored**. |
| **Countable and uncountable** | **How many** fields? **How much** data? |
| **Comparatives** | This format is **more precise than** the old one. |
| **Modals of obligation** | The amount **MUST** carry a currency code. |
| **The zero conditional** | **If** the first digit **is** four, the request **was** wrong. |

**1B  Listen and repeat.** %%AUD KS2-00-01%%

### 2 · What an interface promises

%%FIG b00-f2 | Three numbered boxes in a column. Each one has a kind of promise named in bold, a line reading what it gives the other side, and a line reading what it costs you, with an arrow at the foot pointing to a box reading somebody you will never meet, depending on you.%%

**2A  Read. Then say the three promises to your partner in your own words.**

| | What the other side gets | What it costs you |
|---|---|---|
| **1 What the fields are** | they can write code once | you cannot rename one quietly |
| **2 What happens on failure** | they can handle it without asking you | you must describe failures as carefully as success |
| **3 How long it will last** | they can plan their quarter | you must announce an ending, early |

An interface is three promises, and the third is the one teams forget. The first two are written in
a document. The third is written in a date.

**2B  Listen.** %%AUD KS2-00-02%%

### 3 · The four questions of this book

%%FIG b00-f3 | A card taped inside a laptop lid, printed with four questions in bold, each with one line of smaller type under it explaining when to ask it.%%

**3A  Read the four questions. Which one would have saved you time last month?**

> **1  Is that the description or the service?**
> *Before anybody says the API supports it.*
>
> **2  What happens to a field you did not mention?**
> *Before a schema goes into a document.*
>
> **3  Is that safe, or idempotent, or neither?**
> *Before a client retries anything.*
>
> **4  Who is obliged by this, and by when?**
> *Before a date in a header is treated as a commitment.*

**3B  Ask your partner all four. Answer from a system you work on.**

### 4 · Two sides of one document

%%FIG b00-f4 | Two columns side by side. The left column is headed the side that writes it and lists three lines; the right column is headed the side that reads it and lists three different lines; an arrow at the foot points to a box reading the same sentence, two readings.%%

**4A  Read the two columns. Then discuss: which side are you on this week?**

| The side that writes it | The side that reads it |
|---|---|
| knows what was meant | knows only what was written |
| can see the code | can see the document |
| remembers the reason | has to guess the reason |

Every argument in this book happens in the gap between those two columns. The writing lessons in
this book are all about making the gap smaller — and the reading lessons are about noticing when
somebody else has left it wide open.

**4B  Listen and read.** %%AUD KS2-00-03%%

**4C  One question to finish.** What does your own interface document not say, that a stranger would
need?
