@TASK Part 5: Rules That Protect People
@RUBRIC Read the text and choose the correct answer.
@TEXT
Communications standards are often described as a burden, and in a busy week they feel like one. It is worth remembering what each of them is actually for. The rule that every figure must be checked against a written report exists because memory rounds numbers in the organisation’s favour, never against it, and because a figure that is wrong by a little is quoted back for years. The rule that a name, a face or a location must not be published without consent for that particular use exists because consent is specific: a person who agreed to a photograph in a local newsletter did not agree to a donor report read in six countries. The rule that personal data is kept only as long as it is needed exists because data nobody uses is data somebody can lose. And the rule that a published mistake is corrected openly, on the same channel, in the same week, exists because the alternative — quietly editing a post and hoping — destroys more trust in one evening than a correction ever has. An organisation working in six countries must also accept that its own standards are not the whole picture. Each office follows the law where it works, and where the two differ, the stricter rule applies. That is inconvenient, and it is not negotiable, because the person protected by the stricter rule does not care which document it came from.

@TASK Part 5: Privacy and Trust Across Borders
@RUBRIC Read about data across countries. Then mark each sentence True (T) or False (F).
@TEXT
An organisation that works in several countries holds personal data that crosses borders every day, usually without anybody thinking about it. A consent form signed in one country is scanned and stored on a server in another. A list of beneficiaries is attached to an email and read in a third. None of this is unusual, and none of it is automatically wrong, but it means that the question ‘who can see this, and under which country’s law?’ has to be asked before the file is created rather than after it has been shared. The practical answer most teams reach is data minimisation: collect less, keep it for less time, and share only what the other person actually needs. A donor who wants to know whether a project works does not need names; they need numbers. A colleague in another office who is editing an article does not need the consent forms; they need to know that consent exists. Teams that apply this habit find that most difficult questions never arise, because the data that would have caused the problem was never collected in the first place.
